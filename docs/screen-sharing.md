# 操作 macOS 自带“屏幕共享”

skfiy 直接操作已经连接的 **Screen Sharing / 屏幕共享**（`com.apple.ScreenSharing`）窗口。无需给远端安装组件，也不需要另配 SSH。先用系统客户端完成连接，在需要控制的连接里启用“控制”模式。本机 skfiy 仍需要辅助功能和屏幕录制权限。

## 从截图开始

在同一个 MCP 会话中调用：

```json
{"app":"com.apple.ScreenSharing"}
```

交给 `get_app_state`。多个连接时，用返回的窗口编号明确选中一个：

```json
{"app":"com.apple.ScreenSharing","window":"145498"}
```

返回的是这个连接窗口的独立截图。文字中的 `Shared screen region` 给出远端画面在截图中的区域；区域外是本机工具栏。缩放、Retina 和屏幕位置由截图几何映射处理，**所有 x/y 都是最新截图的像素坐标**，不要使用远端显示器的原始分辨率坐标，也不要手工减去工具栏高度。截图中看不见的远端区域要先通过客户端缩放或滚动显示出来。

远端按钮和文本框是画面里的像素，没有远端辅助功能节点。`get_app_state` 默认做 OCR；不需要时传 `ocr: false`。本机工具栏里的缩放、观察/控制等按钮仍是普通元素编号。

## 后台操作

以下参数分别交给相应工具，窗口编号和坐标换成实际截图里的值：

```json
{"app":"com.apple.ScreenSharing","window_id":"145498","x":320,"y":240}
```

- `click`：上面的参数；右键加 `mouse_button: "right"`，中键用 `"middle"`，双击加 `click_count: 2`。
- `type_text`：`text: "Hello 123"`。支持可打印 ASCII、换行和 Tab，最多 2000 个 UTF-16 单元。远端输入法、键盘布局仍会影响最终文字。
- `press_key`：普通键，例如 `enter`、`backspace`、`left`、`F5`；可用原有的 `repeat` 和 `hold_seconds`。
- `scroll`：`x/y`、`direction: "up" | "down"`（横向滚轮会在发送前拒绝，可拖动远端水平滚动条）、`pages`。
- `drag`：`from_x/from_y` 和 `to_x/to_y`；起终点必须在同一个远端画面内。

这些路径不激活或抬升本机客户端、不移动本机鼠标。每次输入后重新读取连接窗口，刷新坐标和连接身份。输入发送并不证明远端应用完成了操作，必须检查结果画面；若截图失败，回复会保留“输入已发送”的说明，不能盲目重发。

截图在输入开始时须为最近 30 秒内取得。只读树（`screenshot: false`）会使之前的输入坐标失效。窗口移动、缩放导致画面区域改变、连接断开或身份变化时，需要重新查看。键盘只发送到刚才查看且仍持有客户端键盘目标的 `SharedScreen`，不会自动切到别的连接。长字符串和拖拽期间也会检查目标；变化时停止，回复会提示可能已有部分输入到达。

## 快捷键和文字限制

Apple 客户端在后台不会可靠转发 Command、Control、Option 等修饰键状态。普通后台工具会在发送前拒绝这种组合键；`focus: true` 不会把它偷偷转成抢焦点操作。

需要远端快捷键时，明确使用原有的 `run_in_front`，例如：

```json
{"app":"com.apple.ScreenSharing","key":"cmd+a","reason":"在刚查看的远端窗口中全选"}
```

**前台快捷键路径已实现，但本轮未完成最终端到端验收。**它沿用 skfiy 的前台批准流程，短暂改变本机焦点和窗口层级，然后恢复。远端快捷键绕过本机菜单匹配与 skfiy 剪贴板逻辑，因此不会把远端的 Command-A 当成本机菜单命令。若要求完全不改变本机焦点，就不要使用这个路径。

原生客户端会把常规 Unicode 事件按虚拟键码解释，例如把某些中文或 emoji 事件误发成 `a`。因此当前版本在发送任何字符之前拒绝整段含非 ASCII 字符的文字。可通过远端输入法用 ASCII 按键输入，或由用户手动输入；这不是直接 Unicode 输入支持。

skfiy 不自动切换观察/控制模式，不处理远端登录、解锁或权限确认。系统客户端的剪贴板同步由用户现有设置决定；这里的文字输入不借用本机剪贴板。远端文字和按键参数在 skfiy 操作日志中脱敏，因为画面不能可靠区分普通字段与密码字段。

## 验证范围

原生输入路径通过真实的 Apple Screen Sharing 客户端连接本机临时 RFB 测试画面验证。测试服务直接记录收到的按钮、坐标、键码和释放事件，画面随输入改变；这比只检查工具返回“已发送”更直接。它不导出真实桌面，也不会向用户已有的远端连接发送输入。

```bash
make test
python3 scripts/test_screen_sharing.py .build/debug/skfiy --accept
```

第二条需要本机保持解锁，并允许测试连接认证和显式前台快捷键检查短暂使用前台。测试其余部分持续采样本机前台和窗口层级，检查鼠标与剪贴板变化，结束后关闭自己的连接和回环监听端口。测试用英文系统客户端的登录按钮名称匹配认证框。

真实 macOS 服务器上的应用响应、高性能连接、HDR、全屏/多显示器切换及其他系统版本仍需分别验收；本机 RFB 夹具通过不能替代这些场景的证据。

当前实测证据覆盖后台左键、双击、右键、中键、ASCII/换行/Tab、方向键重复、上下滚动和拖拽的 RFB 回执，以及 Unicode、后台 Command 组合键、越界拖拽、纯树读取后的输入、窗口缩放后旧坐标的拒绝。一次后台阶段的 154 个采样没有看到客户端被激活或置顶。

整套端到端验收尚未通过：本机键鼠操作和应用切换会干扰指针与焦点恢复断言，需要空闲桌面重测；当前需要用户批准的前台 HID 快捷键路径尚未完成实测。上述后台分项证据不能替代这些检查。
